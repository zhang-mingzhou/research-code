%% 表注 兩組使用相同任務、來源包、工具定義和評分規則；僅改變 max_steps。這是學生自建固定規則控制器，不是教師 fixture 或 LLM 的能力評測。

最容易出錯的步驟是由「找到來源」跳到「使用來源」：搜尋只回傳標題，並未提供可支持主張的完整卡片。若未讀取便引用，校驗器會拒絕。因此三步失敗是合約未完成，不應解讀為已讀內容不正確。

完整流程最少需要搜尋一次、讀取三次、組合一次、校驗一次，共六次工具呼叫。這個步數結果由工具拆分方式決定；若工具支援批次讀取或合併組合與校驗，門檻便會不同。六步成功不能推論多給步數一定提高任務品質。

校驗器檢查引用來源是否存在且已讀、證據編號是否有效、主張是否與卡片一致，以及篇幅和章節是否符合合約。測試亦覆蓋假引用、未讀來源與竄改主張。這是一致性檢查，不是對原論文科學結論的自動裁決。

所有 trajectory.jsonl 和 tool-results.jsonl 均由本次程式執行產生；provenance.json 明確聲明模型、API、網路與教師 fixture 均未使用。來源卡片的摘要由 Codex 協助整理，作者提交前須核對其準確性。下一步優先取得教師來源包和 validator，再用相同預算重跑；其後測試來源歧義、缺失及錯誤復原。
