# 第二章　文獻綜述

## 2.1　選題與篩選規則

研究範圍限於影像—文字模型的物體幻覺，不納入純文字或音訊幻覺。沿用 W03 的五篇核心文獻：POPE、HallusionBench、VCD、Fact-RLHF 與 Mirage。後四篇均為 2024 年以後的正式會議出版，其中兩篇 CVPR 2024 及一篇 NeurIPS 2025 滿足近期頂會要求。文獻按評估、推理緩解、訓練對齊及批判性再評估分類。

%% 表格题注 表 2　五篇核心文獻的結構化比較

| 文獻 | 研究角色與方法 | 可支持的證據 | 主要限制 |
|:-----------|:-------------|:------------|:------------|
| POPE，EMNLP 2023 [@pope2023] | 以是非問題檢查物體存在性 | 比較不同負例採樣下的回答 | 不涵蓋完整長文本幻覺 |
| HallusionBench，CVPR 2024 [@hallusion2024] | 以控制問題診斷影像語境推理 | 檢查答案一致性與視覺錯覺 | 診斷案例不等同日常任務分佈 |
| VCD，CVPR 2024 [@vcd2024] | 原始及擾動影像的解碼對比 | 檢查免訓練推理介入 | 效果依賴模型與解碼設定 |
| Fact-RLHF，Findings ACL 2024 [@fact2024] | 以額外事實資訊增強獎勵模型 | 比較對齊與事實一致性 | 需要偏好資料與訓練資源 |
| Mirage，NeurIPS 2025 [@mirage2025] | 重審對比解碼的分數增益 | 分析回答分佈與合理性篩選 | 結論不能延伸至所有緩解方法 |


## 2.2　知識結構與批判性判斷

五篇文獻形成三個相互依賴的問題群：評估方法界定何謂錯誤；緩解方法決定在哪個環節介入；批判性再評估檢查指標是否足以支持機制主張。它們並非同一排行榜，不能直接比較不同模型與基準上的分數。

本報告的研究問題由 VCD 與後續再評估的分歧形成：當模型、問題和解碼策略固定時，改善來自假陽性減少、假陰性減少，還是回答分佈移動？因此復現保留混淆矩陣與逐題預測，而非僅保存平均分數。

{{< pagebreak >}}

## 2.3　一頁文獻綜述摘要

視覺語言模型能回應影像問題，卻可能在輸出中加入影像不存在的物體。這個問題需要分別處理評估的有效性與緩解方法的有效性：一項方法在特定基準上得分較高，不足以證明其回答更有視覺依據。

在評估路線上，POPE 以物體存在性的二元問題與不同負例採樣建立可控制的測量；HallusionBench 將檢查延伸到影像語境推理與視覺錯覺。兩者互補，但均不能完整替代開放式描述的事實檢查。早期 CHAIR 的出發點亦顯示，文字相似度未必能充分懲罰不存在物體的描述 [@chair2018]。

在緩解路線上，VCD 以原始和擾動影像的輸出差異重新解碼，不需要重新訓練；Fact-RLHF 則以事實資訊與人類偏好改善對齊。兩條路線的介入層級、資料需求及成本不同。課程實作採 VCD 作為復現對象，將訓練式方法保留於比較背景。

Mirage 對對比解碼的後續研究指出，評測增益需要與輸出分佈及合理性篩選一起分析。由此，本報告將復現目標收斂為「在固定條件下追蹤每一道答案如何改變」。若改善只發生於被誤判為不存在的真實物體，應描述為正例召回改善；若不存在物體的 Yes 回答減少，才支持該設定下的假陽性下降。

後續工作需同時保留小型可重跑測試與較廣泛的評估。小型測試適合查核程式、指標及資料來源；較大規模與多基準測試才能支持較強的模型能力主張。本次摘要的價值在於形成可執行的研究問題，而非將五篇論文逐一改寫成摘要。

# 第三章　技術復現

## 3.1　選定方法與實作

復現對象為 Leng 等人的 VCD [@vcd2024]。程式以原始影像分數 $z$ 和擾動影像分數 $\tilde{z}$ 計算 $(1+\alpha)z-\alpha\tilde{z}$，再移除原始分數低於最大值加 $\log\beta$ 的詞彙。擾動採官方 sigmoid 排程，共 1,000 步，使用第 500 步；固定 $\alpha=1$、$\beta=0.1$。

W03 原規劃使用 LLaVA-1.5-7B；本次在本機改用 SmolVLM-256M-Instruct [@llava2024; @smolvlm2025]，並縮小資料量。這保留影像擾動、雙分支分數及 APC 的核心運算，但不同於原模型、完整基準及採樣設定。因此成果屬方法移植與簡化復現，不是原論文數值再現。

## 3.2　資料、環境與控制變因

從 POPE 的 COCO 共同影像池固定抽樣 12 張，保留 Random 和 Adversarial 各 72 題 [@pope2023; @coco2014]。兩子集各有 36 題 Yes、36 題 No，共用 36 道正例；144 筆題目只有 108 個不重複配對。抽樣在推理前完成，未按結果挑選案例。

使用 RTX 4060 Laptop GPU 8GB，Python 3.10.22、PyTorch 2.5.1+cu121、Transformers 4.51.3，模型以 float16 推理。比較一般解碼、APC-only、VCD；固定影像、問題、提示詞、模型版本、雜訊種子和貪婪解碼。回答以明確 Yes／No 開頭時停止，最多 8 個 token。

同一前綴的原始與擾動分數可重用，以減少重複計算；因此執行時間不作為方法速度比較。完整計算約 155.5 秒，峰值 CUDA 配置記憶體約 2438.7 MiB，僅描述本次實作。程式未呼叫 API，所有答案來自實際模型。

## 3.3　指標與正確性檢查

Accuracy 衡量全體答對比例；Precision 和 Recall 分別檢查 Yes 的可靠性及正例覆蓋；F1 綜合二者；Yes ratio 顯示回答傾向。逐題保留原文、預測、標籤及 token 分數。APC-only 在貪婪解碼下不得改變原始最大值，此性質作為實作檢查。

VCD 令兩子集的 Accuracy 各上升 1.39 個百分點，但只有一個不重複題目由錯改對，沒有假陽性被修正。這不足以確認原論文在其他模型或完整基準上的結論。與原論文可比較的是核心公式、擾動流程和控制條件；表中數字不應直接與原文表格相減後稱為復現誤差。

以影像群集做 2,000 次配對 bootstrap，Accuracy 差值的探索性 95% 區間在兩子集均為 0 至 4.17 個百分點。資料量小、群集僅 12 個且雜訊種子未重複，故不使用「顯著改善」的措辭。

## 3.5　改變案例與失敗分析

影像 246999 的電視題由 No 改為 Yes。這是同一正例在兩子集的重複，應只算一個案例。VCD 仍保留 Adversarial 子集中影像 275863 的 dining table 假陽性。下一步應擴充影像與雜訊種子，檢查新增正例辨識是否同時帶來更多錯誤 Yes。

環境建立曾遇到模型主站連線及資料下載問題，後以公開模型鏡像與 COCO 官方 S3 來源取得檔案。保存版本及 SHA-256 以追溯輸入。故障處理未改寫模型預測或官方標籤；下載途徑與實驗來源分別記錄。

# 第四章　Agent 工作任務

## 4.1　任務合約與證據來源

任務為搜尋離線來源包、讀取三份相關來源，生成一頁含 citation 的研究簡報並校驗最終狀態。教師來源包與 validator 未取得，因此建立學生來源卡片和獨立校驗器，標記 teacher_approved=false。這是替代原型，尚不能宣稱通過教師指定 validator。

來源卡片依 POPE、VCD 和 Mirage 的正式來源整理，另加入 W05 與 W07 的干擾卡片。卡片中的中文內容是本專案整理，不冒稱論文原句。工具介面包含 search、read、compose、validate；只允許來源 ID 白名單，執行時不使用網路、不下載模型、不執行任意 shell。

## 4.2　工具迴圈與步數比較

控制器根據觀測結果決定下一個工具：搜尋結果決定待讀來源，已讀集合決定是否可組合簡報，再檢查產出狀態。這借鑑工具互動的基本結構 [@react2023]，但不含真實 LLM 推理。固定規則的流程可精確重跑，代價是不能據此評估自主規劃能力。

| 3 | 3 | 2 | 0 | 未通過 |

三步條件只完成搜尋和兩次讀取，final-brief.md 為空；空檔保留失敗狀態，不由人工補寫。六步條件完成三份來源讀取、六條證據引用及自建校驗。兩組的外部評分規則相同，外部校驗不計入 Agent 工具呼叫。

{{< pagebreak >}}

## 4.3　兩頁內分析與限制

最容易出錯的步驟是由「找到來源」跳到「使用來源」：搜尋只回傳標題，並未提供可支持主張的完整卡片。若未讀取便引用，校驗器會拒絕。因此三步失敗是合約未完成，不應解讀為已讀內容不正確。

完整流程最少需要搜尋一次、讀取三次、組合一次、校驗一次，共六次工具呼叫。這個步數結果由工具拆分方式決定；若工具支援批次讀取或合併組合與校驗，門檻便會不同。六步成功不能推論多給步數一定提高任務品質。

校驗器檢查引用來源是否存在且已讀、證據編號是否有效、主張是否與卡片一致，以及篇幅和章節是否符合合約。測試亦覆蓋假引用、未讀來源與竄改主張。這是一致性檢查，不是對原論文科學結論的自動裁決。

所有 trajectory.jsonl 和 tool-results.jsonl 均由本次程式執行產生；provenance.json 明確聲明模型、API、網路與教師 fixture 均未使用。來源卡片的摘要由 Codex 協助整理，作者提交前須核對其準確性。下一步優先取得教師來源包和 validator，再用相同預算重跑；其後測試來源歧義、缺失及錯誤復原。

## 4.4　提交檔案

每個條件保留 final-brief.md、task-contract.json、tool-schema.json、trajectory.jsonl、tool-results.jsonl、evaluation.csv、error-note.md、provenance.json，並額外保存 validation.json。比較表位於 agent/runs/comparison.csv。六步簡報可作為工作成果閱讀，三步目錄則保留完整失敗證據。

# 第五章　平時作業整合與反思

W01 的結構化精讀用於區分問題、方法與證據；W02–W03 直接提供選題及文獻地圖。W04–W06 的參數比較啟發單變因設計。W07–W10 的重跑、provenance、評分和錯誤筆記被沿用到新實驗。原有教師 fixture 的數字只作流程練習，未被當作 VCD 或真實 Agent 結果。

本次交付的核心是把每項結論連回可核查的輸入、程式和輸出。真實模型實驗與固定規則 Agent 原型屬不同證據類型；明確區分它們，比增加無法支持結論的圖表更重要。AT4 將在此基礎上集中討論「分數改善是否等於幻覺減少」，不將三項作業機械拼接成研究結論。
